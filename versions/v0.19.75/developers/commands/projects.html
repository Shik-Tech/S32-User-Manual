Projects and storage ​

bash
s32 --loopback list
s32 --loopback active
s32 --loopback storage
s32 --loopback pull internal 1 /tmp/p1.s32p
s32 --loopback push /tmp/p1.s32p
s32 --loopback push /tmp/p1.s32p --volume sd
s32 --loopback --yes push /tmp/p1.s32p --volume sd --activate

list and active are aliases for project list and project active.

Library ​

CommandNotes
list* marks the active project. Answers busy while the card is still reading its project list, and for a moment after the card drops out
activeDirty flag and generation
storageProjects, capacity, and free space on each storage, and job state. Sizes are in bytes. microSD cards larger than 4 GB show their full size with firmware 0.19.52 or later
pull VOLUME UID OUT.s32pVOLUME is internal or sd. Copies that project and checks the checksum. A damaged copy is not written. A missing card is not found
push IN.s32p [--volume internal|sd] [--activate]--volume defaults to internal. --activate prompts (or --yes) and loads the new project
project create VOLUME NAME [--seed empty|daw]
project delete VOLUME UIDPrompts
project rename VOLUME UID NAME
project duplicate VOLUME UID NAME [--to internal|sd]Prints the source uid and job handle. Without --to, the copy stays on VOLUME. --to puts it on the other storage. job HANDLE then prints that copy's volume and uid.
project load VOLUME UIDPrompts; replaces the live session
project saveWrite the live project in place
project save --waitSame write, then wait until it is stored and print elapsed_ms
project save-as VOLUME NAME [--activate] [--wait]Saves the live project, unsaved changes included, as a new project on VOLUME. Prints the new uid, the job handle, and activate=on or activate=off. --wait also prints elapsed_ms and the job state once it is stored
abortCancel an in-flight push

internal is onboard storage. sd is microSD. list answers busy while the card is still reading its project list, and for a moment after the card drops out. Try it again. Once the card has been out long enough, the list no longer shows its projects. pull sd copies a card project. push --volume sd copies a project file onto the card as a new project. A missing card is not found. If the card is still reading its project list, the push answers busy. Try it again. If that read fails, the push answers a storage error. Take the card out and put it back in before trying again. A damaged file is not stored. Stopping the push leaves no new project. If the card stalls during the push, the editor stays usable.

project duplicate --to sd copies a project that is already on the S32 onto the card. --to internal copies a card project onboard. If the card is still reading its project list, the copy answers busy. Try it again. If that read gives up, the copy answers a storage error. Take the card out and put it back in before trying again. A missing card is not found. A destination with no room answers no space. The copy is a new project. The one you copied from stays where it was.

project save-as is Save As for the project you are playing. The project it came from keeps what was last saved. Without --activate you stay on that project and its unsaved changes, so a later project save still writes it. With --activate, the new project becomes the active one once it is stored, with no unsaved changes, and its name shows in capitals like any other project. If the card is still reading its project list, or a storage job is running, it answers busy. Try it again. A missing card is not found, a storage with no room answers no space, and a project that is still loading answers not ready. If the card is pulled while it saves, the job fails and nothing else changes. Check with job HANDLE.

project save, save-as, load, create, delete, rename, and duplicate answer busy while a pull or push is still open. Retry when the transfer finishes.

bash
s32 --loopback --yes project create internal Scratch --seed empty
s32 --loopback --yes project load internal 2
s32 --loopback project save
s32 --loopback project save --wait
s32 --loopback project save-as internal "Take 2"
s32 --loopback project save-as sd Gig --activate --wait

project save --wait prints elapsed_ms once that save is stored.

A push without --activate stores a record and does not change the live project. Confirm with active after both forms.

If a push is interrupted, knobs and MIDI keep working. The project you are playing stays as it was. Keep a pull copy so you can try the push again.

Files ​

.s32p is a full project record. Archive it, restore it with push, or decode it with the layout JSON from s32 layout --emit-layout-json.
