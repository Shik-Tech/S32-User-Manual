Racks and devices ​

text
s32 --loopback repl
s32> rack list
s32> rack rename 0 Lead
s32> device add 0 step-seq
s32> device list 0
s32> stepseq set 0 1 step 0 active=1 note=60 vel=100
s32> stepseq get 0 1
s32> rack duplicate 0 1
s32> rack set 1 bypass=on

RACK and DEV are positions: rack 0 is the first rack, device 0 the first device in it. Ids (rack list, device list) are used only by lfo assign and macro set … mode=device.

Racks ​

CommandWhat it does
rack listPosition, id, bypass, device count and name of each rack. An empty slot's id prints -
rack rename RACK NAMEKeeps the first 10 characters
rack set RACK bypass=on|offBypasses the whole rack
rack clear RACKAsks first. Removes every device
rack duplicate SRC DSTAsks first. Overwrites the destination rack

Devices ​

CommandWhat it does
device list RACKPosition, type, id and name of each device
device add RACK TYPEAdds a device to the rack. TYPE is a name (midi-in, midi-out, clock, arp, step-seq, …) or its number from schema
device remove RACK DEVRemoves the device. Its LFO assignments and external MIDI mappings are removed; a knob macro on it keeps its rack and shows SET TARGET. MIDI IN or CLOCK in first place stays while other devices are in the rack.
device move RACK FROM TOReorders inside the rack. MIDI IN stays first, MIDI OUT last
device param get RACK DEV PARAMValue and range
device param set RACK DEV PARAM=VALUE [PARAM=VALUE …]One or more settings in one sentence. Rounded to a whole number and clamped to the range
device param action RACK DEV PARAMPresses that row's button, like Select on the panel: randomize (Step Seq), record or reset (Looper), or a PARAM number. A normal row answers BadRequest
device host-device RACK DEVWhich USB Host device a MIDI IN or MIDI OUT uses: ALL or a device name
device host-device RACK DEV host=all|N|NAMEPicks ALL, or a device from host-device list by number or name. The name runs to the end of the line, so it can hold spaces

An empty rack takes MIDI IN or CLOCK first. A device that can't go there, or a full rack, answers BadRequest. NoSpace means the S32 has no room for another device.

PARAM is a parameter name (bypass, mode, rate, gate, clock-division, port, host-device, …) or its number from schema, not the row on the screen.

USB Host devices ​

host-device list prints the devices this project knows on the USB HOST port, numbered as HOST DEVICE counts them (0 is ALL). A device you unplugged stays listed, marked (unplugged). stored is the name exactly as the project keeps it, in the case the device reported; it is left out when the device has no name. device host-device matches the panel text, not stored, so pick a second identical device by its number.

text
s32> host-device list
host devices: 4 of 8
  0 ALL
  1 KEYBOARD  (1209:0001 at 011)  stored "Keyboard"
  2 KEYBOARD (2) (unplugged)  (1209:0001 at 012)  stored "Keyboard"
  3 SYNTH (unplugged)  (1209:0002 at 021)  stored "Synth"
  4 1209:0003  (1209:0003 at 031)
s32> device host-device 0 0 host=keyboard
rack 0 device 0 HOST DEVICE = KEYBOARD

HOST DEVICE only does something while that MIDI IN or MIDI OUT has PORT set to USB HOST.

IN SNAPSHOT and ALLOW MORPH for device parameters are under snapshot flags.

Step Seq ​

stepseq get RACK DEV prints all 16 steps. DEV must be a Step Seq.

stepseq set RACK DEV step N key=value … changes one step (0–15). Keys: active, note, vel, gate, ch, prob.

Output after a set ​

rack rename and rack set print the rack's row, device param set one line per parameter, device host-device ... host= the HOST DEVICE and stepseq set the pattern (A set prints the state it left):

text
$ s32 --loopback rack rename 0 Lead
rack 0 renamed
  [0] id=100  bypass=off in=yes devices=1 Lead
$ s32 --loopback device param set 0 0 port=4
rack 0 device 0 param port (149) set
rack 0 device 0 param port (149) = 4.000 (0.000..127.000)
$ s32 --loopback device host-device 0 0 host=all
rack 0 device 0 HOST DEVICE = ALL
rack 0 device 0 HOST DEVICE = ALL

device host-device already read the HOST DEVICE back, so the same line prints twice: your confirmation, then the read-back.

With --json, device param get and device param set print one object with a params array (one entry per parameter, in the order given). device host-device --json is {"rack":0,"device":0,"host":"ALL","value":0,"connected":true,"listed":true}: host is the stored name without (unplugged) (or null for a number the list does not hold), connected is false exactly when the text says (unplugged), and listed is false exactly for (not listed).
