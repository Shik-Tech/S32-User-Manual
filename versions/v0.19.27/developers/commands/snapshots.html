Snapshots ​

bash
s32 --loopback snapshot list knobs
s32 --loopback snapshot arrange get
s32 --loopback snapshot arrange set repeat=loop rate=1 knobs=0,5
s32 --loopback snapshot sequence get knobs
s32 --loopback snapshot morph get knobs

PART is knobs, lfos, or rack0…rack7.

List, store, recall, delete, rename ​

CommandNotes
snapshot list [PART]Names and occupancy. Default part is knobs
snapshot store PART [SLOT|next] [NAME]Capture live state. Empty-rack store is BadRequest until that rack has a device
snapshot recall PART SLOTQueue a recall. Does not drop project-ready
snapshot delete PART SLOTRAM + dirty
snapshot rename PART SLOT NAMENames only; does not recapture
snapshot flags get|set device RACK DEV PARAM [on|off yes|no]Per-parameter IN SNAPSHOT (on/off) and ALLOW MORPH (yes/no)
snapshot flags get|set lfo s32|cv16 INDEX PARAM [on|off yes|no]Same flags for one S32 or CV16 LFO parameter
snapshot parent get|set lfo s32|cv16 INDEX [on|off]IN SNAPSHOT for that whole LFO
snapshot parent get|set device RACK DEV [on|off]IN SNAPSHOT for that whole MIDI device
snapshot copy|swap|move PART SRC DESTCopy/swap/move persist payloads. Fade-blocked is Busy. Empty copy/move source is NotFound
snapshot jump ROWJump the Arrange playhead to ROW (0–255). Same as snapshot arrange jump ROW
snapshot queue ROW|offArm Drop on ROW, or off/none/cancel to clear. Same as snapshot arrange queue

Do not send store / recall / delete / copy / jump at a live user project over USB. Loopback and a throwaway CLI-HIL project (SCENARIO=snapshots) are the safe mutate paths.

IN SNAPSHOT ​

Each macro, each whole LFO, and each whole MIDI device has one live IN SNAPSHOT switch. Each parameter has its own switch. Both default to on. Recall, fade, and morph move a parameter only when both switches are on. Off leaves that value where it is. Take still stores the whole scene. Recall does not write either switch, and the switches are not stored in the snapshot.

snapshot flags reads and writes the per-parameter switch (and ALLOW MORPH). snapshot parent reads and writes the switch for a whole LFO or a whole MIDI device. macro get prints in=on or in=off, and macro set … in=on|off writes the switch for one macro. lfo cfg set does not change the LFO switch.

Morph ​

snapshot morph get|amount|clear PART … — live fade toward one pad. get prints pinA unset and pinB as the target pad. Amount is 14-bit (0–16383). Above 0 it arms toward the occupied active slot, starting from what is playing now. 0 is your own sound: on a bank with no morph it is accepted and does nothing, and on a live morph it ends the morph once 0% is sounding (get then reads morphing=0). clear drops the fade. Firmware answers Busy while fade-on-recall owns the engine.

text
s32> snapshot morph amount knobs 8192
morph amount part=knobs 8192
s32> snapshot morph get knobs
part=knobs pinA=- pinB=0 morphing=1 amount=8192
s32> snapshot morph amount knobs 0
morph amount part=knobs 0
s32> snapshot morph get knobs
part=knobs pinA=- pinB=- morphing=0 amount=0

Sequence (one column) ​

snapshot sequence get PART and snapshot sequence set PART rate=… [steps=…] edit one Arrange column (up to 256 cells). rate is 1–128 bars (shared across the song). steps is up to 256 comma-separated slots or rest. Shorter lists pad with rest to the current song length.

Arrange (song grid) ​

snapshot arrange get prints Repeat, Rate, length (4–256), live song-row, drop-row (none when no Drop is armed), then each part’s cells for that length.

snapshot arrange set is GET-modify-SET. Pass only the fields you want to change:

text
s32> snapshot arrange set repeat=once rate=4 knobs=0,5 lfos=0,rest,3 rack0=0,2

repeat is loop or once. Column keys are the same part names as snapshot list. A short column list replaces that whole column and pads the rest of the song-length cells with rest (same as snapshot sequence set). Omitted columns keep their current cells. SET does not write Jump/Drop — use snapshot jump / snapshot queue. view nav snapshot-lane stays panel-only (Forbidden).

Mapping ​

extmap add / macro set accept target=snapshot-slot and target=morph-amount with part=…. An LFO cannot target either. A target=morph-amount macro has no MIN/MAX: min= and max= are ignored and macro get prints min=0.000 max=16383.000. invert= still flips it. The panel has no PICKUP row for it: a MORPH knob always picks up, whatever pickup= reads. A target=snapshot-slot macro’s min= and max= are snapshot slots 1–32. The knob skips empty slots inside that window. Assigning that target with a number outside 1–32 uses the full 1–32 window. Changing min= or max= on a macro that is already a snapshot slot to a number outside 1–32 is refused. in= is forced off for both targets (macro get prints in=off).

To make either one a normal macro again, give it a new mode= (or rack=, device=, param=, cvParam=) without target=. The macro leaves the snapshot role, in= turns back on, and MIN/MAX become the new mode's full range. A device setting gets its own range from the S32 (Delay Time reads 0–1000). Add in=, min=, or max= to the same sentence to set them yourself:

text
s32> macro set 0 0 mode=cc msb=7
s32> macro get 0 0
pot 0 macro 0: mode=cc msb=7 … min=0.000 max=127.000 … in=on … cvOut=255 lfo=255 name=
