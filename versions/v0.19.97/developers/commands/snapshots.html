Snapshots ​

text
s32 --loopback repl
s32> snapshot store knobs next Verse
s32> snapshot store knobs next Chorus
s32> snapshot list knobs
s32> snapshot recall knobs 0
s32> snapshot bank set knobs 1bar 1/4

PART is the bank: knobs, lfos, or rack0…rack7. SLOT is 0–31. See Snapshots for how banks work on the S32.

Slots ​

CommandWhat it does
snapshot list [PART]Names, which slots are full, and the active one. Default knobs
snapshot store PART [SLOT|next] [NAME]Takes the current sound into a slot. A rack bank with no devices answers BadRequest; Busy during a fade
snapshot recall PART SLOTRecalls a slot
snapshot delete PART SLOTEmpties a slot. Busy during a fade
snapshot rename PART SLOT NAMERenames without taking again
snapshot copy|swap|move PART SRC DESTBusy during a fade. An empty source answers NotFound

Bank settings ​

snapshot bank get PART and snapshot bank set PART SYNC FADE.

Values
SYNCimmediate, 1bar, 2bars, 3bars, 4bars
FADEoff, 1/16, 1/8, 1/4, 1/2, 1bar, 2bars, 4bars

IN SNAPSHOT ​

Each macro, each whole LFO and each whole device has an IN SNAPSHOT switch. So does each parameter. Recall, fade and morph move a parameter only when both its switch and its owner's switch are on. A take still stores everything. Recall doesn't change the switches.

CommandSwitch
snapshot flags get|set device RACK DEV PARAM [on|off] [yes|no]One device parameter: IN SNAPSHOT (on/off) and ALLOW MORPH (yes/no)
snapshot flags get|set lfo s32|cv16 INDEX PARAM [on|off] [yes|no]The same for one LFO parameter
snapshot parent get|set device RACK DEV [on|off]A whole device
snapshot parent get|set lfo s32|cv16 INDEX [on|off]A whole LFO
macro set KNOB MACRO in=on|offOne macro

Morph ​

snapshot morph get|amount|clear PART … fades live toward the active slot. Amount runs 0–16383. Above 0 it starts from what is playing now. 0 ends a running morph. clear drops it. While a recall fade is running the answer is Busy. See Morph.

In a fresh s32 --loopback repl:

text
s32> snapshot store knobs next Verse
s32> snapshot morph amount knobs 8192
morph amount part=knobs 8192
s32> snapshot morph get knobs
part=knobs pinA=- pinB=0 morphing=1 amount=8192
s32> snapshot morph amount knobs 0
morph amount part=knobs 0
s32> snapshot morph get knobs
part=knobs pinA=- pinB=- morphing=0 amount=0

Arrange ​

Arrange plays slots as a song: up to 256 rows, one column per bank.

snapshot arrange get prints repeat, rate, length, the playing row (song-row), the armed QUEUE (drop-row, none when off), then each column.

snapshot arrange set changes only the keys you name:

KeyValues
repeatloop or once
rateBars per row, 1–128
lengthRows, 4–256
knobs, lfos, rack0…Slots and rest, comma-separated. A short list fills the rest of the column with rest
text
s32> snapshot arrange set repeat=once rate=4 knobs=0,1,0,1 lfos=0,rest,3

snapshot sequence get PART and snapshot sequence set PART rate=… [steps=…] edit one column the same way.

CommandWhat it does
snapshot jump ROWMoves the playhead to ROW (from 0)
snapshot queue ROWArms a QUEUE on ROW. snapshot queue off disarms it

Mapping ​

macro set and extmap add take target=snapshot-slot or target=morph-amount with part=PART. LFOs can't target either.

  • Snapshot slot: min= and max= are slots 1–32, as on the screen. The knob skips empty slots. A number outside 1–32 on assignment gives the full 1–32.
  • Morph amount: always 0–16383. min= and max= are ignored. invert= still works. It always picks up.

Both turn IN SNAPSHOT off for that macro. To make it a normal macro again, set a new mode= (or rack=, device=, param=, cvParam=) without target=. IN SNAPSHOT comes back on and the range becomes the new mode's full range:

text
s32> macro set 0 0 target=morph-amount part=knobs
s32> macro set 0 0 mode=cc msb=7
s32> macro get 0 0
